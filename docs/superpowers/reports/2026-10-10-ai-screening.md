# 쓸모 AI 평가 · 건물주 페이지 · 쓸모 트랙 결과 보고 (2026-10-10)

브랜치: `feat/ai-screening` (main에는 손대지 않음). 설계: `docs/superpowers/specs/2026-10-10-ai-screening-design.md` §1–11, 시안 `docs/mockup-v8.html`.

## 만든 것
- **마이그레이션 `0004_ai_screening.sql`**: 공간(위치 정보·건물주 토큰·순이익률·환산 배수), 신청(트랙·동의·AI 결과 필드·결과 메일 시각), `consulting_months`(쓸모 트랙만 허용하는 트리거), `educator_links`.
- **순수 로직(테스트 먼저)**: 예상 매출(`revenue.ts`), 후보 선정(`shortlist.ts`: 60점 이상, 최대 5명, 동점은 먼저 신청한 순), AI 출력 검증(`ai-report.ts`), 프롬프트 빌더(`ai-prompt.ts`: 이름·이메일 없음을 테스트로 고정), 수수료(`consulting.ts`: 이익>0일 때 매출×1%), 월 기록·교육자 파서, 동의 파서(AI 동의 항상 필수, 컨설팅 동의는 쓸모 트랙만).
- **평가기**: `fake`(결정적)와 `anthropic`(fetch, `claude-sonnet-5-5`, SDK 없음). 신청 저장 후 `ctx.waitUntil`로 실행, 실패는 `failed`+오류 저장, 관리자 재평가.
- **결과 메일**: `RESEND_API_KEY`+`MAIL_FROM`이 있으면 링크만 자동 발송, 없으면 링크 복사+“보냄” 체크. 발송 슬롯을 원자적으로 잡아 중복 발송 방지.
- **화면**: R1 `/r/:slug`(예상 매출·근거·면책·쓸모 트랙 박스), P6' `/apply/:slug`(트랙 선택·동의), P8' `/result/:token`(판정·요약·5개 항목 리포트, 점수 숨김, 입금/유료 피드백 UI 제거), O1 `/o/:token`(후보 최대 5장, 3장 후 더 보기, 이름·이메일·계획 원문 없음, 모르는 토큰 404), A4'(위치 정보·순이익률·환산 배수·건물주 링크 생성/복사/재생성·후보 미리보기), A5'(AI 리포트·재평가·결과 전달·월별 기록과 수수료·교육자 연결). 브랜드 문구 썰모→쓸모.
- **시드**: 모든 신청에 가짜 평가기 결과·트랙. 시드 쓸모 트랙 `최예시`(seongsu-01)에 2개월 기록(흑자 수수료 10만원, 적자 0원).

## 확인 방법
`npm ci && cp .dev.vars.example .dev.vars && npm run db:migrate && npm run db:seed && npm run dev` (Node 24). 관리자 `admin@ssulmo.local / ssulmo-dev`.
- 건물주 페이지: `/o/` + `o`×32 (망원동), `/o/` + `p`×32 (성수동, 후보 5명 + 더 보기).
- 결과 페이지: `/result/` + `a`×32, `b`×32, `c`×32 (망원동), `1`…`8` ×32 (성수동). 모집 페이지 `/r/seongsu-01`, 신청 `/apply/seongsu-01`.
- 관리자: `/admin`, 공간 상세(건물주 링크), 신청 상세(AI·월별 기록).

## 판단(Rulings)과 틀렸을 때 비용
1. **키가 없으면 가짜 평가기 사용**(지시문대로 `EVALUATOR=fake` 또는 키 없음). 운영에서 `ANTHROPIC_API_KEY`를 빠뜨리면 실제 신청자에게 가짜 점수가 나가고 메일·건물주 페이지에 노출됨(`ai_model='fake'`로 식별 가능). 비용: 높음 → 배포 전 키 확인 필수. 대안은 운영에서 `EVALUATOR=anthropic`일 때 키 없으면 실패 처리(권장 후속).
2. 평가 제한시간 25초(`waitUntil`은 응답 후 약 30초에서 끊김) — 긴 PDF·느린 응답은 `failed`가 되고 재평가로 재시도. 틀리면 실패가 잦음(중간). 근본 해결은 Queue.
3. 건물주 페이지도 공간 동의 해제 시 404(리뷰 반영, 테스트 있음). 동의 전에 링크를 만들어 보여줄 수는 없음.
4. 자유 입력 업종은 키워드로 설문 업종에 매핑(젤라또→아이스크림·디저트); 매핑 실패 시 추정치 0으로 프롬프트에 들어감 — 평가 품질만 영향(낮음).
5. AI 동의 문구를 “사업계획 글에 직접 적은 개인정보는 그대로 전달”로 수정(리뷰 반영). 문구 자체는 TODO(legal).
6. 이메일 자동 발송 실패 시 관리자 화면에 링크 복사+체크 유지(리뷰 반영).
7. 시드의 성수동 신청은 8건(6건 통과·1건 60점 미만·1건 실패)로, 지시의 7건과 후보 조건이 충돌해 조정.
8. 건물주 토큰 페이지는 점수를 “참고용”으로 보여줌(시안 그대로), 지원자에게는 점수 숨김.

## 보류된 사소한 항목
- 재평가 중·실패 시 이전 결과가 지원자에게 “평가 중”으로 바뀜.
- `/o`·`/result`에 `Referrer-Policy: no-referrer`, `Cache-Control: private` 헤더 미설정.
- `.pdf` 확장자만으로 PDF 판별(이름만 바꾼 파일은 400으로 실패).
- 트리거는 INSERT만 검사(트랙을 나중에 일반으로 바꾸면 고아 기록), `consent_ai_at`은 DB 제약 없이 파서만 강제.
- 존재하지 않는 id 재평가 검사 없음, “1%” 문구가 `FEE_RATE`와 별개로 하드코딩.
- 평가가 오래 `pending`인 신청을 관리자 목록에서 구분하는 표시 없음.
