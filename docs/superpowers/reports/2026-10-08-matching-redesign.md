## 만든 것
- **디자인 시스템(A)**: Noto Sans KR, 황금비 타입 스케일(16/25.9/41.9/67.8px, 캡션 12.6px, 행간 1.618), 잉크·파스텔 노랑/초록 토큰(주황 제거), 드래그 선택 느낌의 반투명 하이라이트(화면당 헤드라인 1개), 1px 얇은 카드 테두리, `keep-all` 줄바꿈, 모바일/PC(≥1024px, 최대 1180px, 상단 내비) 반응형. 전 화면 적용. 설문의 업종은 3개 카테고리 카드(먹거리/생활/배우기·운동).
- **창업 자리 매칭(B)**: `/find` (`/spaces`는 301로 이동). 정했어요 → 업종(카테고리 카드) → 이용 의향 인원순 추천, 아직이에요 → 구 선택 → 구별 공간과 1위 업종(2·3위는 PC에서). 고정 문구 "응답자 N명 중 M명이 이용 의향". 50명 미만은 숫자 없이 "집계 중", M=0 제외, PC 3장/모바일 1장 후 "더 보기". "이 업종으로 지원해보기" → `/apply/:slug?type=…` 프리필.
- `migrations/0003_space_district.sql`, 관리자 공간 등록에 구(필수) 추가.
- 순수 로직 `app/lib/matching.ts`(테스트 우선 작성).

## 판단(Rulings)과 틀렸을 때 비용
1. 더 보기는 모든 카드를 렌더하고 CSS로 숨김 — 틀리면 카드가 많아질 때 HTML 크기만 늘어남(낮음).
2. 업종 검색에서 50명 미만 공간은 M>0일 때만 "집계 중"에 표시 — 숫자는 없지만 "누군가 선택"이 암시됨(낮음, 스펙의 'M=0 제외'를 따름).
3. 구 미지정(NULL) 기존 공간은 "상관없어요"에만 노출 — 마이그레이션이 구를 채우지 못한 행은 보이지 않을 수 있음(낮음).
4. `?type=` 프리필은 40자 제한(신청 폼·서버와 동일) — 리뷰에서 60자 불일치를 발견해 테스트 먼저 수정.
5. `/spaces`는 301 — 다시 쓸 일이 생기면 캐시 때문에 302로 바꿔야 함(낮음).
6. 선택 단계는 링크 이동 방식, 목업의 실시간 집계 aside는 생략(낮음).
7. 하이라이트는 홈·설문·리포트·구 결과 헤드라인에만 1개씩.

## 보류된 사소한 항목
- 관리자 화면에서 기존 공간의 구 수정 UI 없음.
- `any` 센티널이 `?district=` 값과 같은 이름공간(관리자 폼이 구로 끝나는 값만 허용해 현재 무해).
- 공개 리포트에 막대 그래프 없음(로더에 수치 없음).
